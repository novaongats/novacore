# NOVACore 教訓集

## 2026-03-02: NovaSync全面修正 + 全機能検証

### 発見された根本原因パターン

1. **forcePushAll の自動実行はデータ消失の主犯** — ログイン時や起動時にlocalStorageをFirebaseに無条件上書きすると、他デバイスの最新データが消える。自動pushは廃止し、個別push（変更時のみ）に限定すべき。

2. **バージョンマイグレーションでのデータ消去は危険** — 新デバイスでlocalStorageが空の状態でデータをremoveItemすると、その後のpushで空データがFirebaseに上書きされる。

3. **Firebase リスナーの重複登録** — `.off()` を呼ばずに再接続のたびに `.on()` を登録すると、リスナーが蓄積し同じイベントが複数回発火する。フラグで制御。

4. **配列データの丸ごと上書き** — 2台が同時に異なるレコードを追加すると片方が消える。idベースのマージが必要。

### 発見されたバグパターン

5. **関数エイリアスの不整合** — `escH` vs `escHtml`。新機能追加時に既存ユーティリティ関数名を確認せずに短縮名を使用。

6. **同名関数の二重定義** — `renderMonthlyReport` が月報用と発注用の2箇所で定義され、後者が前者を上書き。同じスコープ内の関数名は一意にすること。

7. **要素IDの不一致** — `monthlyTarget` が存在しないのに参照。コピペ時にIDを修正し忘れ。

8. **iframe間の関数名齟齬** — `handleCSVExport`/`handleExport`/`importInput` が別iframeの関数名・要素IDのまま残存。各iframeはスコープが独立しているため、コピペ時に関数名・要素IDを必ず確認。

9. **CSSセレクタの不一致** — JS側 `.sync-badge` vs HTML側 `.bdg-sync`。名前変更時に全参照箇所を検索して更新すること。

10. **@media print CSSの欠如** — 印刷ボタンがあるiframeに印刷用CSSが無いと、UI要素がそのまま印刷される。

11. **CSS規則の切り詰め** — 長い行を手動編集した際にCSSルールが途中で切れることがある。

### 印刷レイアウトパターン

12. **`!important` が print CSS を上書き** — `nc-embed-override` のような画面用スタイルシートで `!important` を使うと、`@media print` 内の通常ルールが負ける。画面専用ルールは `@media screen{}` で囲むこと。

13. **ポップアップウィンドウにCSS変数が引き継がれない** — `window.open()` で作った新ウィンドウには親のCSS変数 (`var(--text)` 等) が存在しない。インラインHTMLではハードコード値 (`#333` 等) を使うこと。

14. **ネストされた `@page` はCSS仕様上無効** — `#element { @page { size: A4; } }` はブラウザに無視される。条件付きページサイズ変更はJSでの動的制御が必要。

15. **`@page` ルール無し = ブラウザデフォルト** — 請求書のようなフォーマルな文書には必ず `@page { size: A4; margin: ... }` を定義すること。

16. **`print-color-adjust: exact` の明示** — 背景色や文字色が印刷で消える場合は `print-color-adjust: exact; -webkit-print-color-adjust: exact;` を追加。

17. **印刷時に非表示にすべき要素** — フィルタバー、追加ボタン、アクションボタンは必ず `.no-print` を付与。モーダルは `.modal`/`.modal-overlay` を print CSS で `display:none` にすること。

### CSS変数パターン

18. **`--nv-*` と `--nc-*` の混同** — `nv-*-fix` スタイルブロックが `--nv-*` 変数を参照していたが、定義は `--nc-*` のみ。CSS変数のプレフィックスは統一し、未定義変数は `var()` に渡さないこと。未定義の `var()` は無効値となり、プロパティが無視される。

19. **CSSの宣言順でのカスケード上書き** — `nv-*-fix` ブロックが `nc-modern` / `nova-unified` の後に来るため、同じ `!important` でも後者が勝つ。後から来るブロックの変数が未定義だと、正しい前のルールが上書きされて壊れる。

20. **`.btn-danger` 等のベーススタイル欠如** — `:hover` のみ定義して基本スタイルが無いと、背景色も文字色も未設定でボタンが見えない。hover だけでなく基本状態も必ず定義すること。

21. **AnCore の `:root` に `--bg-secondary` / `--red-light` 未定義** — CSS変数を使用する前に `:root` で必ず定義すること。変数追加時は `:root` ブロックとの整合性を確認。

## 2026-07-14: v2完成作業（feature/v2-complete）

22. **htm は未クローズの `<br>` を許容しない** — `<br>` と書くと以降の兄弟要素がすべて br の子として飲み込まれ、コンポーネントが途中までしか描画されない。htm テンプレート内の void 要素は必ず `<br/>` と自己クローズすること。（料率設定タブが丸ごと消えた根本原因。既存5ファイルにも同じ潜在バグがあった）

23. **CSSクラスをページの `<style>` に置くと他ページで無スタイルになる** — `.note` が settings.js 内にのみ定義され、給与や売上ページの `.note` は素のdivだった。複数ページで使うクラスは styles.css へ。

24. **ローカル開発でルートURLを開かない** — ルートは旧アプリ（index.html）で、開いた瞬間に Service Worker 登録 + NovaSync の Firebase RTDB 同期が走る。v2の開発・確認は必ず /v2/ 配下のURLで行う。SWが /v2 のフェッチもキャッシュするため、モジュール更新が反映されない事故も起きる（今回 unregister 済み）。

25. **v2の標準報酬「0=自動」規約** — employees.js は未入力を 0 で保存する。計算側で `!= null` 判定すると 0 が手動値扱いになり社保が0円になる。`> 0` で判定すること。

26. **旧→新のフィールド名正規化は importer で一元的に** — 旧レコード（grossSalary/netSalary/bonusAmt）を素通しすると新UIでは¥0表示になる。スキーマが違うデータの移行は spread ではなく明示的マッピング。

## 2026-07-14: 品質レビュー第1波（6並列レビュー→4並列修正）

27. **オーバーレイ印刷は「body直下ポータル + #app非表示」が正解** — `body * { visibility:hidden }` ハックはページ内オーバーレイの祖先（.app-shell/.main の overflow:hidden、body の height:100vh）にクリップされ、「サイドバー分ズレた1ページだけのPDF」になる。v2/print.js の PrintPortal（createPortal で body 直下に描画 + `body.has-print-overlay #app { display:none }`）に載せれば通常フローで page-break が機能する。新しい印刷オーバーレイは必ずこれを使う。

28. **`@page` ルールは文書順カスケードに注意** — head で管理する `@page { size: A4 landscape }` を、コンポーネント内 styleBlock の `@page { size: A4 }` が上書きして横向きが効かない事故。@page の管理箇所は1つに集約する。

29. **「初回ログイン時に自動シード」は権限昇格穴になりやすい** — プロフィール欠落時に admin でシードするクライアントコードは、saveProfile 失敗→次回ログインで誰でも admin という穴。自動シードは最小権限（staff/home）に限定し、Firestore ルール側でも self-create の内容を制約する。

30. **onSnapshot のエラーを console.error だけで握り潰さない** — permission-denied 時に loading が永遠に true になり「無限スケルトン」化する。購読エラーは必ず error state に配線し、data を空にして loading を解除する。

31. **消費税の端数処理は「1請求書につき税率ごとに1回」** — 明細行ごとの丸めはインボイス制度の要件違反（取引先の検算と1円ズレる）。税率別にグループ化して合計に対して1回だけ丸める。

32. **max+1 の連番採番は必ず衝突する** — 一覧取得→max+1 は同時編集・オフラインで重複発行になる。Firestore の runTransaction + counters ドキュメントで採番し、採番タイミングは「開いた時」ではなく「保存時」にする。

33. **並列修正エージェントにはファイル所有権を明示的に分割する** — 「このファイル群のみ編集可、他は他担当が編集中なので import のみ可」と明記すれば、4本並列でもコンフリクトゼロで完了できる。共有ヘルパー（shared.js の csvCell 等）は親が先に用意してから配る。

34. **修正指示にも誤りは混ざる — エージェントの反証を歓迎する** — 「taxable − social にせよ」という指示に対し、保存済み taxable が既に社保控除後だと突き止めて不採用にした修正エージェントが正しかった。指示を鵜呑みにせず一次情報（コード・国税庁）で裏取りさせる指示文が有効。

## 2026-07-15: Codex CLI（GPT 5.6 Sol）との敵対的レビュー連携

35. **codex exec はバックグラウンド実行だと stdin 待ちで固まる** — 引数渡しでも「Reading additional input from stdin...」で待つ。`codex exec - < prompt.txt`（ファイルからstdinリダイレクト）でEOFを届けるのが確実。
36. **PowerShell 5.1 のパイプは日本語を化けさせる** — `Get-Content | codex` は $OutputEncoding（既定ASCII）で化ける。日本語プロンプトは Git Bash のリダイレクトで渡す。
37. **codex exec のフラグはサブコマンドの前に置く** — `codex exec --sandbox read-only resume <id>` が正。resume の後に置くと unexpected argument。
38. **モデル容量エラーで最後に死んでもセッション再開で回収できる** — `codex exec resume <session-id> "続きを出力して"` で34万トークン分の調査コンテキストを引き継ぎ、最終レポートだけ出させられる。
39. **敵対的クロスレビュー（Claude×GPT）は実際に見逃しを拾う** — 3波の自前レビュー後でも、GPT側だけが「令和8年度税制改正の2026年分年調」「賞与10倍超の特殊計算」「給与所得控除の表引き精度」を新規指摘。逆に印刷・権限・集計整合はClaude側のみ。役割: Claudeは構造・整合、GPTは法令网羅の粗探しに強かった。
40. **レビュー依頼プロンプトには「実装するな、指摘リストが成果物」と明記** — 曖昧だと「実装済みで問題なし」という検証レポートに化ける（文字化け時に実際に発生）。
